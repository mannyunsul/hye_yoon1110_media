## 1. Railway 백엔드 배포

백엔드(yt-dlp 미디어 추출 서버)를 Railway에 올리는 과정입니다.

### 1-1. GitHub에 코드 올리기

```bash
cd C:/work/myeon/workspace/hye_yoon1110
git init          # 아직 git 저장소가 없다면
git add backend/
git commit -m "feat: add backend server"
```

GitHub에서 새 저장소를 만들고 push:

```bash
git remote add origin https://github.com/YOUR_ID/hye-yoon-backend.git
git push -u origin main
```

### 1-2. Railway에서 배포

1. [railway.app](https://railway.app) 접속 → 로그인 (GitHub 계정 권장)
2. **New Project** → **Deploy from GitHub repo** 선택
3. `hye-yoon-backend` 저장소 선택
4. 설정 화면에서 **Root Directory**를 `backend`로 변경
5. **Deploy** 클릭

Railway가 자동으로:

- Node.js 감지 및 `npm install` 실행
- `nixpacks.toml`을 읽어 Python + yt-dlp 설치
- `node server.js`로 서버 시작

### 1-3. 배포 URL 확인 및 동작 테스트

배포 완료 후 Railway 대시보드에서 URL 복사 (예: `https://hye-yoon-xxxx.railway.app`)

```bash
# 헬스체크
curl https://YOUR-URL.railway.app/api/health
# 예상 응답: {"status":"ok"}

# 미디어 추출 테스트 (공개 게시물 URL)
curl -X POST https://YOUR-URL.railway.app/api/fetch \
  -H "Content-Type: application/json" \
  -d "{\"url\": \"https://x.com/NASA/status/1234567890\"}"
```

### 1-4. 앱에 URL 적용

> 로컬 개발(`quasar dev`)과 앱 빌드(`quasar build`)에서 URL이 자동으로 분리됩니다.

**로컬 개발용** — `frontend/.env.development` (이미 설정됨):

```
VITE_BACKEND_URL=http://localhost:3000
```

→ `quasar dev` 실행 시 자동으로 로컬 서버 사용

**앱 빌드용** — `frontend/.env.production` 파일에서 Railway URL 교체:

```
VITE_BACKEND_URL=https://hye-yoon-xxxx.railway.app   ← 실제 URL로 교체
```

→ `quasar build` 시 자동으로 Railway URL 사용

따라서 **로컬에서 백엔드 서버를 띄워두고 `quasar dev`로 개발**하다가,  
**APK 빌드 전에만 `.env.production`의 URL을 Railway URL로 바꿔주면** 됩니다.

## 2. Android APK 빌드

### 전제 조건

- Android Studio 설치: [developer.android.com/studio](https://developer.android.com/studio)
- JDK 17 이상
- Android SDK (Android Studio 설치 시 자동 설치됨)

### 2-1. Android 플랫폼 추가

```bash
cd C:/work/myeon/workspace/hye_yoon1110/frontend
quasar build -m capacitor -T android
```

빌드 완료 후:

```bash
cd src-capacitor
npx cap add android    # 처음 한 번만 실행
npx cap sync android
```

### 2-2. AndroidManifest.xml 권한 추가

`src-capacitor/android/app/src/main/AndroidManifest.xml` 파일을 열어서  
`<manifest>` 태그 바로 아래에 아래 권한을 추가:

```xml
<uses-permission android:name="android.permission.READ_MEDIA_IMAGES" />
<uses-permission android:name="android.permission.READ_MEDIA_VIDEO" />
<uses-permission android:name="android.permission.READ_EXTERNAL_STORAGE"
    android:maxSdkVersion="32" />
<uses-permission android:name="android.permission.WRITE_EXTERNAL_STORAGE"
    android:maxSdkVersion="29" />
<uses-permission android:name="android.permission.INTERNET" />
```

### 2-3. Android Studio에서 APK 빌드

```bash
npx cap open android
```

Android Studio가 열리면:

**디버그 APK (테스트용):**

1. `Run > Run 'app'` → 에뮬레이터 또는 실기기 선택
2. USB 디버깅이 활성화된 실기기 연결 권장

**릴리즈 APK (배포용):**

1. `Build > Generate Signed Bundle / APK`
2. `APK` 선택 → `Next`
3. 키스토어 생성 (처음이라면 `Create new...`) 또는 기존 키스토어 선택
4. `release` 빌드 선택 → `Finish`
5. 완료 후 `app/release/app-release.apk` 생성됨

### 2-4. 실기기 테스트 체크리스트

APK 설치 후 아래 항목을 순서대로 확인하세요:

- [ ] 앱 실행 시 하단 탭 4개 표시 (관리/미관리/다운로드/설정)
- [ ] **다운로드 탭**: SNS URL 입력 → "미디어 가져오기" → 미리보기 표시
- [ ] **다운로드 탭**: 태그 입력 후 "저장" → 관리 탭에서 항목 확인
- [ ] **북마크 모드**: 파일 저장 없이 URL만 등록되는지 확인
- [ ] **관리 탭**: 썸네일 탭 → 바텀 시트 열림, carousel 스와이프 동작
- [ ] **관리 탭**: 롱프레스 → 퀵 메뉴 (출처 열기 / 태그 편집 / 전체 삭제)
- [ ] **미관리 탭**: 갤러리 스캔 결과 표시, 다중 선택 후 태그 등록
- [ ] **설정 탭**: 백업 내보내기 → 공유 다이얼로그 열림
- [ ] **설정 탭**: 백업 가져오기 → JSON 파일 선택 후 복원 동작
- [ ] **설정 탭**: 사용 가이드 보기 → 가이드 페이지 이동

## 문제 해결

### Railway 배포 실패

- yt-dlp가 설치되지 않는 경우: `backend/nixpacks.toml` 파일이 있는지 확인
- 포트 오류: Railway는 `PORT` 환경변수를 자동 주입함, `server.js`에서 `process.env.PORT` 사용 확인

### APK 설치 후 갤러리 스캔이 빈 화면인 경우

- 기기 설정 → 앱 → 미디어 매니저 → 권한 → 사진 및 동영상 권한 허용

### 미디어 다운로드가 안 되는 경우

- `.env.production`의 `VITE_BACKEND_URL`이 올바른 Railway URL인지 확인
- Railway 대시보드에서 서버 로그 확인
